# AI 工具使用指南（CodeX / WorkBuddy / Trae）

> 本工作台提示词库的 12 条业务提示词（写邮件/做分析）**三个工具通用**——它们产出的是文字，不依赖工具特性。
> 真正需要区分工具的是**工程类提示词**（改代码、加功能），本文给出三工具的差异用法与模板。

---

## 一、三工具特性速查

| | CodeX（CLI Agent） | WorkBuddy（对话式） | Trae（IDE Agent） |
|---|---|---|---|
| **形态** | 终端里的编码代理 | 对话框助手 | IDE 内嵌 Chat/Builder |
| **最强项** | 按指令批量改仓库文件 | 边聊边生成内容，无需环境 | 多文件编辑 + 实时 diff 预览 |
| **给上下文方式** | 让它自己读文件（说清路径） | 手动粘贴关键内容到对话 | `@文件名` 精准引用 |
| **改代码可靠性** | 高（能跑测试/自查） | 低（只出代码，自己拷） | 高（所见即所得的 diff） |
| **适合本工作台** | 二开功能、批量重构 | 写邮件/文案/翻译（配合提示词库） | 日常小改、调样式、加字段 |

**选型口诀**：写字用 WorkBuddy，小改用 Trae，大动干戈用 CodeX。

## 二、业务提示词怎么用（12 条通用）

1. 在本工作台「AI 提示词」页找到场景 → 点「复制提示词」（变量已填充）→ 粘到任意工具
2. 【】占位符（客户名/询盘原文等）粘贴后手动替换
3. 对产出不满意时，追问模板：`保留结构，把语气改得更____ / 长度压到____ / 换一个切入角度：____`

## 三、工程提示词三工具模板（同一个需求三种写法）

以「给客户档案加一个"主营品类"字段」为例：

**CodeX 版**（指令式，给足路径）：

```text
在本仓库（AI-Trade-Workbench）给客户档案增加「主营品类」（category）字段：
1. server/index.js 的 POST/PUT /api/clients 接受 category 字段
2. src/types.ts 的 Client 接口加 category: string
3. src/views/Clients.tsx 的新增表单和列表列各加一项
4. seeds/clients.json 示例数据补上该字段（用 [PLACEHOLDER] 占位）
改完跑 npx tsc --noEmit 确认无类型错误，再总结你改了哪些文件。
```

**WorkBuddy 版**（贴关键代码，分段对话）：

```text
我在做一个 React+Express 的客户管理小应用。先把这段类型定义和表单代码给你：
【粘贴 src/types.ts 的 Client 接口 + Clients.tsx 表单片段】
请帮我加一个「主营品类」字段：类型里加 category: string，表单里加一个输入框并提交到后端。只给我需要改动的代码段，并标明改哪个文件。
```

**Trae 版**（@ 引用，多文件一次说清）：

```text
@src/types.ts @src/views/Clients.tsx @server/index.js
给客户档案加「主营品类」category 字段：类型定义、新增表单、列表列、API 白名单四处一起改，保持现有代码风格。
```

## 四、三条军规（三个工具通用）

1. **一次一件事**：提示词末尾加「只改 X 相关内容，其他一律不动」；
2. **改完先看 diff 再接受**（Trae/CodeX 都有 diff 视图；WorkBuddy 出的代码贴回前先读一遍）；
3. **git 兜底**：满意的改动立刻 `git add -A && git commit -m "…"`，改坏随时 `git checkout -- .` 一键还原。
